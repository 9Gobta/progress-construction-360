# Spatial Warp Points ตามแนวทาง OpenSpace

เอกสารนี้บันทึกเหตุผลทางเทคนิคและขอบเขตของต้นแบบ ไม่ได้อ้างว่าใช้ source code
หรือโมเดลภายในของ OpenSpace ซึ่งเป็นระบบเชิงพาณิชย์

## หลักฐานต้นแบบ

อ้างอิงสิทธิบัตร Open Space Labs `US11386616B2: Automated spatial indexing of
images based on floorplan features` ระบบประกอบด้วยขั้นสำคัญดังนี้

1. แยกภาพ 360 จากวิดีโอและใช้ feature-based SLAM เพื่อประมาณ 6D camera pose
   (ตำแหน่งสามมิติและการหมุนสามมิติ) ของภาพแต่ละภาพ
2. จัดแนว camera path เข้ากับ floor plan โดยใช้จุดเริ่มต้นและคุณลักษณะของแบบ
3. คำนวณ route vector ด้วยผลต่างตำแหน่งสามมิติของภาพต้นทางกับภาพปลายทาง
4. กรอง route vector ตามระยะและสิ่งกีดขวาง เช่น กำแพง
5. ฉาย geometry ของวงแหวนด้วย projection matrix และ view matrix ของผู้ชม
6. เมื่อเลือกวงแหวน ให้เปิดภาพ 360 ที่เป็นหัวของ route vector นั้น

แหล่งอ้างอิงหลัก:

- https://patents.google.com/patent/US11386616B2/en
- https://www.openspace.ai/the-tech/

## สิ่งที่ต้นแบบทำแล้ว

- ทุก Camera Pose ที่มีพิกัดครบถูกแสดงเป็น Warp Point ไม่สุ่มหรือลดจำนวนจุด
- จุดเรียงตาม Timestamp และใช้พิกัดเดียวกับ Dense Capture Path
- API สร้าง spatial graph จาก Warp Points ที่มี pose และอยู่ชั้นเดียวกัน
- รักษาเส้นเชื่อมไปจุดก่อนหน้า/ถัดไปตามเส้นทาง และเพิ่มจุดใกล้เชิงพื้นที่
- จำกัดไม่เกิน 4 route vectors ต่อภาพเพื่อลดวงแหวนซ้อนกัน
- ส่ง `delta_x`, `delta_y`, `delta_z`, ระยะ และ bearing ของทุกลิงก์ให้เว็บ
- Viewer แปลง route vector จากพิกัดแบบเป็นพิกัดสัมพัทธ์ของ panorama
- Three.js projection คำนวณตำแหน่งวงแหวนใหม่ทุกเฟรมเมื่อผู้ใช้หมุนหรือซูม
- ปุ่มแต่ละวงผูกกับ `to_keyframe_id` จริง
- SfM ดึงแกน zero-longitude ของ panorama จาก rotation ของ cubemap camera
  แทนการใช้ทิศการเดินเป็น orientation ของภาพ

## ข้อจำกัดปัจจุบัน

- การกรองเส้นผ่านกำแพงยังไม่เปิดใช้ เพราะแบบชั้น 1 ปัจจุบันเป็นภาพ raster และยังไม่มี
  wall/door mask ที่เชื่อถือได้ เส้นเชื่อมจึงกรองด้วยชั้น ระยะ และเพื่อนบ้านตามเวลา
- พิกัดแปลนเก็บแบบ normalized; ระยะใน API จึงเป็นอัตราส่วนของภาพแบบ ไม่ใช่เมตร
- วิดีโอที่เคย Localize ก่อนการแก้ orientation ต้องสั่ง `คำนวณ AI ใหม่` เพื่อสร้าง
  camera poses ด้วย pipeline รุ่นใหม่
- เป้าหมายความแม่นยำ 80% ต้องวัดกับ ground-truth points ที่ผู้ตรวจทำเครื่องหมาย
  ไม่ควรใช้ confidence score ของโมเดลแทนค่าความแม่นยำจริง

## เกณฑ์ตรวจรับ Warp Point

1. หมุน panorama แล้ววงแหวนต้องเคลื่อนตาม scene และหายเมื่ออยู่หลังมุมมอง
2. เลือกวงแหวนแล้ว `selected keyframe` ต้องเท่ากับ `to_keyframe_id`
3. จุดปัจจุบันบนแปลนต้องเปลี่ยนเป็น pose ของภาพปลายทาง
4. ภาพคนละชั้นต้องไม่ถูกเชื่อมกัน
5. ทุก Warp Point ที่ไม่ใช่จุดโดดเดี่ยวต้องมีทางเดินต่ออย่างน้อยหนึ่งเส้น
6. ทดสอบตำแหน่งด้วยจุด ground truth ไม่น้อยกว่า 20 จุด ก่อนรายงานความแม่นยำ
