# Thesis workspace

The thesis teammate owns this directory. Application code changes belong to
the product-development workstream.

## Suggested chapter files

1. `01-introduction.md` — background, problem, objectives, scope
2. `02-literature-review.md` — 360 capture, visual localization, VSLAM, BIM,
   construction progress, and related systems
3. `03-methodology.md` — research design, inputs, workflow, data model,
   localization method, human inspection, and evaluation
4. `04-system-design.md` — architecture, UX, permissions, and data lifecycle
5. `05-implementation.md` — implemented components and important decisions
6. `06-results.md` — reproducible results only
7. `07-discussion.md` — interpretation, limitations, and threats to validity
8. `08-conclusion.md` — conclusions and future work

Create chapter files only when their outline and evidence are ready. Keep
citations in `source-register.md`, unresolved items in `open-questions.md`, and
advisor decisions in `decision-log.md`.

## Definition of a reviewable section

- Every number has a source or test artifact.
- Current scope and archived experiments are clearly separated.
- Method, result, and interpretation are not mixed together.
- Limitations are explicit.
- Figures have a source path, caption, and capture/test date.
- No confidential data appears in the text or image.
